## 1. АРХИТЕКТУРА ПРОЕКТА

Godot 4.7 (Forward Plus, физика Jolt). Главная сцена `scenes/main.tscn` —
единственная, содержит один Node3D со скриптом `scripts/game.gd`. Вся игра
строится кодом (процедурно), сцен в редакторе почти нет. Весь UI рисуется
вручную в `_draw()` (`scripts/ui.gd`). Весь звук синтезируется при запуске
(`scripts/audio.gd`), внешних аудиофайлов нет.

```
game.gd (GrannyGame, Node3D)        — контроллер: состояния, взаимодействия, замки, шумы, endings
├── world_builder.gd (WorldBuilder) — мешы уровня (SurfaceTool-батчи), двери, мебель, лампы, капканы, пауки
│   └── world_gen.gd (WorldGen)     — чистая генерация раскладки 4 уровней + распределение предметов
│       └── level_data.gd (LevelData) — тайлы, двери, контейнеры, укрытия, A*, LOS, ai_blocked
├── player.gd (PlayerBody, CharacterBody3D) — движение, стамина, батарейка, укрытия, вьюмодель руки
├── granny.gd (GrannyAI, Node3D)    — FSM: PATROL/INVESTIGATE/CHASE/SEARCH/CLIMB/STAGGER, A*, анти-застревание
├── cat.gd (CatAI, Node3D)          — Маруся: злость на шум/свет/сундук, молоко, мурчание
├── bottle.gd (ThrownBottle)        — баллистика бутылки, разбитие, срабатывание капканов
├── trap_node.gd (TrapNode)         — визуал капкана (челюсти)
├── ui.gd (GameUI, Control)         — весь интерфейс (_draw), миникарта, дневник, экраны
├── audio.gd (autoload "Audio")     — процедурные WAV, пул плееров, музыка/шины
├── items.gd (Items)                — ID, названия, подсказки, иконки (атлас + процедурные)
├── materials.gd (Mats)             — все материалы и процедурные текстуры
├── settings.gd (GameSettings)      — настройки: громкости, мышь, видео; user://settings.cfg
└── save_system.gd (SaveSystem)     — сохранения: user://saves/{auto,slot1..3}.json
```

Состояния игры (game.gd): TITLE, DIFF, INTRO, PLAY, PAUSE, CAUGHT, WIN, OVER,
HELP, SETTINGS, SAVE, LOAD.

Константы тайлов/предметов совпадают со старой C#-версией — не менять значения.

## 9. ПОЛУЧЕНИЕ GODOT 4.7.2 ДЛЯ ПРОВЕРОК (третья сессия)

Release-CDN GitHub (release-assets.githubusercontent.com) в песочнице заблокирован
— готовый бинарник скачать нельзя. Официальный путь, который работает:
**сборка из исходников godotengine/godot, тег 4.7.2-stable** (тарбол через
codeload.github.com — разрешённый хост, 72 МБ).

Конфигурация сборки в песочнице (2 ядра, 3.8 ГБ RAM):
```
scons platform=linuxbsd target=editor dev_build=yes vulkan=no opengl3=no \
  x11=no wayland=no alsa=no pulseaudio=no dbus=no speechd=no udev=no \
  linker=gold -j2 progress=no
```
* dev_build=yes — без оптимизации (компиляция быстрее и память ниже);
* без рендера и дисплей-драйверов — как официальные headless-сборки;
* **linker=gold обязателен**: дефолтный bfd `ld` на финальной линковке
  съедает всю память (OOM-kill, signal 9 при 3.8 ГБ). Gold линкует
  ~1.5 минуты. Проверено дважды.
* pkg-config в песочнице отсутствует — подменён заглушкой
  (/usr/local/bin/pkg-config, «пакет не найден» + валидный --version),
  что и требуется: все системные библиотеки считаются отключёнными.
* Результат: editor-бинарник для `--headless --import` и запуска проекта.

Важно про headless: `RenderingServer.frame_post_draw` в headless не приходит —
тест завис бы на первом скриншоте. В `tests/autotest.gd::_shot` добавлен guard:
при `DisplayServer.get_name() == "headless"` скриншоты пропускаются
(на проверки не влияет). В обычном режиме всё как было.

Инструкция для реальной Windows 11 (движок, импорт, автотест, коды выхода,
фолбэк рендера, чеклист) — `docs/TESTING_WINDOWS.md`. Команда запуска
`--path . -- --autotest` сверена с реализацией (OS.get_cmdline_user_args,
exit code 0/1, печать `AUTOTEST checks=121 fails=N`).

## 11. ПРОГОН В РЕАЛЬНОМ ДВИЖКЕ (четвёртая сессия)

Движок: Godot 4.7.2.stable.custom_build (dev editor, headless), собран по §9.
Импорт: `--headless --import` — rc=0, 48 ресурсов. Автотест — три итерации.

### Прогон 1: checks=121 fails=3 — все три провала расследованы до корня

1. **«open door lets the player through»** — НЕ баг физики. Контрольный
   эксперимент: оригинальный код из d3adc7a (worktree + только headless-guard
   скриншотов) падает с тем же числом (z=13.63) — это предсуществующий
   артефакт headless-темпа: process-кадры идут быстрее physics-тиков (60 Гц),
   за 55 кадров игрок не успевал дойти до двери (~36 тиков). Зонд: те же
   фазы с 150 кадрами → 57/57 OK. Исправление: обе фазы door-проверки
   удлинены до 150 кадров — проверка зависит от геометрии, а не от темпа.
   (Заодно объяснено «57» в исходном README: 54 вызова + 3 из цикла уровней.)
2. **«F11 toggles fullscreen back»** — в headless `Window.mode` всегда
   WINDOWED: после первого F11 `settings.fullscreen=true`, а `win.mode`
   реальное окно не меняет → второй F11 снова считал «нужно в fullscreen».
   Корневое исправление в `game.gd`: тоггл теперь детерминированный по
   самому флагу (`settings.fullscreen = not settings.fullscreen`), win.mode
   только приводится в соответствие; чтение mode после присваивания убрано.
   Проверка в headless остаётся осмысленной (свойство флага), реальный
   режим окна проверяется только на настоящем дисплее.
3. **«slot2 written from UI»** — ошибка индексации в самом тесте, не в игре:
   UI пишет в `ALL_SLOTS[save_idx]`; тест ставил `save_idx=1` («slot1»),
   а читал `SLOTS[1]` («slot2»). Исправлено: `save_idx=2` (ALL_SLOTS[2]
   == "slot2"), читается `SLOTS[1]` — так и задумано (два множества имён).

### Прогон 1 же вскрыл баг шин аудио (исправлен)

`audio.gd::_ensure_buses`: `get_bus_index(name)` вызывался ПОСЛЕ `add_bus()`,
