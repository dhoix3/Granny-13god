# Запуск и тестирование GRANNY 13 на Windows 11 (Godot 4.7.2)

Инструкция проверена на соответствие реализации `tests/autotest.gd`:
аргументы после `--` попадают в `OS.get_cmdline_user_args()`
(`scripts/game.gd`, строка 181), тест сам завершает процесс с кодом
`0` (успех) или `1` (есть провалы) и печатает строку
`AUTOTEST checks=218 fails=N`.

## 1. Требования

| Компонент | Требование |
|---|---|
| ОС | Windows 11 (x86_64), достаточно прав пользователя |
| Движок | **Godot 4.7.2-stable**, **стандартная (не .NET)** сборка — проект целиком на GDScript, C#-вариант не нужен |
| Графика | D3D12 или Vulkan (рендер Forward+); если драйвер капризничает — есть фолбэк `gl_compatibility` (см. ниже) |
| Диск | ~200 МБ (движок ~120 МБ + кэш импорта `.godot/` в папке проекта) |
| Прочее | Python/SCons для запуска тестов **не нужны** (только для сборки самого движка из исходников) |
| Аудио | любое устройство вывода; без него игра тоже запустится (драйвер Dummy) |

## 2. Установка Godot 4.7.2 (официальные источники)

Вариант A — сайт: <https://godotengine.org/download/windows/> →
«Godot Engine — Standard version».

Вариант B — GitHub-релизы: <https://github.com/godotengine/godot-builds/releases/tag/4.7.2-stable>
→ `Godot_v4.7.2-stable_win64.exe.zip`.

Далее:

```powershell
Expand-Archive .\Godot_v4.7.2-stable_win64.exe.zip -DestinationPath C:\Godot
```

Получится два файла: `Godot_v4.7.2-stable_win64.exe` (окно без консоли) и
`Godot_v4.7.2-stable_win64_console.exe` (обёртка с выводом в терминал —
**рекомендую её для тестов**, чтобы видеть `AUTOTEST FAIL:`-строки).

## 3. Первый импорт проекта (один раз)

Импорт создаёт кэш `.godot/` (в .gitignore, в PR не попадает):

```powershell
cd C:\path\to\Granny-13god
& 'C:\Godot\Godot_v4.7.2-stable_win64_console.exe' --headless --import --path .
```

Дождитесь возврата в консоль. Критических ошибок быть не должно.

## 4. Автотест — все 218 проверок

```powershell
cd C:\path\to\Granny-13god
& 'C:\Godot\Godot_v4.7.2-stable_win64_console.exe' --path . -- --autotest
$LASTEXITCODE
```

* Откроется окно игры, тест сам прогонит сценарий (~1–3 минуты) и сам закроет
  процесс. Ввод не требуется.
* В терминале: список `AUTOTEST FAIL: ...` (если есть), затем
  `AUTOTEST checks=218 fails=N` и `AUTOTEST OK` / `AUTOTEST FAILED`.
* `$LASTEXITCODE` = 0 → всё пройдено; 1 → есть провалы.
* Скриншоты перезаписываются в `tests\shots\` (01_title … 19_saves).

### Вариант без окна (headless)

```powershell
& 'C:\Godot\Godot_v4.7.2-stable_win64_console.exe' --headless --path . -- --autotest
```

Все 218 проверок выполняются в этом режиме; скриншоты недоступны в принципе
(в headless движок ничего не рендерит) и пропускаются — на проверки не влияет.

### Примечание о пост-тестовом шуме консоли

Если строка `AUTOTEST checks=218 fails=0`, `AUTOTEST OK` и строки perf frame_ms напечатаны и
`$LASTEXITCODE` = 0 — тест пройден полностью. После этого в **dev-сборках**
Godot в консоли могут появиться Jolt-assertion и предупреждение про leaked
ObjectDB instances — это teardown-шум самой сборки движка после выхода,
на результат не влияет и в release-сборках отсутствует. Игнорируйте его.

## 5. Ручной запуск игры

```powershell
& 'C:\Godot\Godot_v4.7.2-stable_win64.exe' --path .
```

или открыть папку проекта в Godot Project Manager и нажать **F5**.

## 6. Что делать при проблемах

| Симптом | Решение |
|---|---|
| Чёрный экран / ошибка D3D12 | запустить с фолбэком: `--rendering-method gl_compatibility --rendering-driver opengl3` |
| Ошибка Vulkan | то же самое (фолбэк на OpenGL) |
| «Windows защитила ваш компьютер» (SmartScreen) | «Подробнее» → «Выполнить в любом случае» — Godot подписан не всеми сертификатами |
| Тест висит на старте | убедиться, что скачана **4.7.2** (не 4.6/4.8-dev) и что папка проекта не открыта в другом экземпляре Godot |
| `ERROR: No loader found for resource` в импорте | удалить папку `.godot/` и повторить шаг 3 |
| Тест пишет `AUTOTEST FAILED` | приложить к PR весь вывод со строками `AUTOTEST FAIL:` — по ним видно, какая из 218 проверок упала |

## 7. Мини-чеклист перед ревью PR (переработка 2)

1. Шаг 3 (импорт) прошёл без критических ошибок.
2. Автотест: `AUTOTEST OK`, `checks=218 fails=0`, `$LASTEXITCODE` = 0;
   питон-проверка `python3 tests/logic_check.py` → `checks=439 fails=0`.
3. Скриншоты в `tests\shots\` обновились и не выглядят сломанными
   (чёрные кадры в сценариях поимки/победы — норма: это затемнения).
4. Игра запускается вручную, «Новая игра» работает.

## 8. Ручная приёмка переработки 2 (что смотреть глазами)

1. **Рук нет**: предметы парят перед камерой; появление плавное, при ходьбе
   лёгкое покачивание, `X` — осмотр (вращение/наклон/зум), `Q`+ПКМ —
   прицел/выстрел арбалета.
2. **Один предмет**: взять второй без `G` невозможно; тост «руки заняты»;
   обысканный шкаф с вещью подсказывает «Поднять: …».
3. **Дроп живёт**: выбросил ключ у двери — он лежит на полу (биллборд с
   иконкой); сохранился/загрузился/поймался — предмет на том же месте.
4. **Звук**: в доме слышен ветер и случайные скрипы; на чердаке/в подвале
   амбиент меняется без щелчков; звуки за стеной глухие; шаги Гренни
   позиционные, в погоне — дыхание.
5. **Дом**: люки/лестницы по всей высоте (дом↔чердак, дом↔подвал,
   дом↔гараж); коридоры не «пустые», у комнат разный свет и мебель.
6. **Производительность**: Настройки → Качество (Низкий/Средний/Высокий)
   применяются на лету; на слабом ПК/Android выбрать Низкий (без normal-
   карт, меньше источников света).

## 9. Android (план проверки на реальном устройстве)

1. Godot 4.7.2 + Android Build Template; экспорт debug-APK
   (project.godot уже настроен: mobile-рендер, ETC2/ASTC, sensor_landscape).
2. Установить, запустить: тач-джойстик слева, зона осмотра справа,
   кнопки действий; мультитач (идти + осматриваться + действовать).
3. Автотест на устройстве недоступен — вместо этого: а) новая игра →
   первый люк и спуск; б) обыск шкафа с занятыми руками; в) бросок бутылки;
   г) сохранение/загрузка слота; д) FPS глазами на Низком профиле и тепло
   устройства за 15 минут.
4. Известное ограничение песочницы: реального Android-устройства у агента
   нет, APK-экспорт не проверялся — проверка на устройстве за пользователем
   по этому плану.
